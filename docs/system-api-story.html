How Cool-Aid used the System API

Cool-Aid tells a clinic which patients are at risk in a heat wave because of their medicines and their home. Every risk claim has to rest on evidence. The System API was where we found that evidence and how we checked it.

System found the links between 15 medicines and heat, checked the numbers we quote, and caught its own mistakes.

The data

Five kinds of data, joined on shared keys

System is one of five sources. The others give place, regulation and patients. They join on paper IDs (PMID, DOI), medicine group, ZIP code and date.

System Public Graph

  • Live API: 40.3M studies, 5.9M findings, 627k relationships
  • Harvard Dataverse v2.1 bulk release: 2.0M findings, 845k studies, checksums verified
  • PubMed E-utilities for publication dates (1,207 PMIDs)

Literature

  • PubMed + Europe PMC search: 5,995 unique records, 1,965 chased citations
  • Screened down to 333 included papers and 367 extraction rows
  • Our cited list: 83 distinct papers

Regulatory & guidance

  • openFDA drug labels: 5,938 label sections audited → 299 heat sentences
  • FAERS adverse events (21M reports) → 403 signal rows, compared against negative-control drugs
  • 13 heat-health guidance documents → 306 guidance codes

Place & climate (Bronx)

  • NWS HeatRisk forecasts; NOAA station history (26,196 station-days, 183 heat waves)
  • Heat Vulnerability Index, SVI (2,324 tracts), CDC PLACES, air-conditioning access
  • 1,868 cooling places, 520 pharmacies; Medicare Part D prescribing by ZIP

Patients (synthetic)

  • 300 patients, 952 medicines, 327 contacts, calibrated to PLACES, SVI and Part D
  • No real patient data anywhere in the app

Everything flows into one knowledge base: 15 medicine groups, 101 claims, each with a source and a verification badge. The app reads only that.

What System did

Four jobs for the System API

1 · Find38 pathwaysfrom 15,001 findings: how each medicine and heat hit the same weak spot
2 · Check14 numbers ✓✓System extracted the same value from the same paper as us
3 · Spot gaps0 – 2 studiesfor the sweat-blocking medicines, the ones classic heat advice worries about most
4 · Feed the applivestudy counts on every medicine card and in the "how heat and medicine add up" picture

1,902 API calls in total, under the 10,000-a-day limit. Every response is cached, so the whole run can be repeated without spending calls.

Job 1 · Find

From 5.9 million findings to 38 pathways

We asked System for every finding that names one of our medicines, heat, or one of four body effects: dehydration, low sodium, kidney injury and low blood pressure. Then we kept the findings that connect a medicine or heat to one of those effects. Joining the two sides gives a two-step pathway: medicine → body effect ← heat.

Most of these pathways were never studied as "this drug in the heat". System lets us connect two well-studied halves.

Job 2 · Check

System as a second, independent reader

We extracted every number we quote from paper abstracts ourselves. System extracts findings from papers too, so we compared, paper by paper: same number, same meaning, same direction.

Where System read the same paper, it got the same number every time. Zero conflicts.

Job 3 · Spot gaps

Where the evidence is thin

Counting System studies per medicine group shows where the evidence sits. Kidney and fluid drugs are well covered. The medicines that stop sweating or raise body heat (anticholinergics, topiramate, stimulants) are almost absent. That gap is itself a finding: the graph under-represents the mechanism behind several classic heat drugs, so Cool-Aid labels those claims "Early signs" instead of overstating them.

Ground rules

How we kept System honest, and ourselves

  • ✓Our numbers must appear word for word in the abstract. If they don't, the claim is hidden from public views. System can't rescue it.
  • ✓✓Double-verified only when System agrees. 14 numbers. Under System's own advice (about 20% of API extractions are inaccurate, so keep a finding only if it is also in the Dataverse release), 5 survive. We report both.
  • ⚠A System mislabel never downgrades our claim. In 3 papers (7 numbers) System had our number but the wrong drug or none. Our claim keeps ✓; the error goes on a fix list for System.
  • ↗Corroboration is labeled as such. A System relationship that agrees with a claim but isn't the same result shows as ↗, never as proof.
  • !No dose advice, no invented data. Every label and number in the app comes from a file with a source.
